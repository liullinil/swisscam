# SwissCAM

Редактор и симулятор управляющих программ для станков продольного точения (swiss-type).

Цель — не «ещё один CAM с деревом операций», а инструмент технолога у станка:
открыть УП, увидеть её глазами станка, поймать ошибку до того, как её поймает шпиндель.

## Что делает

- **Разбор УП** — многоканальные программы (`$1`/`$2`/`$3`), комментарии, пропуск кадра,
  метки синхронизации, макрокоманды (распознаются, но не исполняются).
- **Интерпретатор** — модальное состояние, G0/G1/G2/G3, дуги по I/K и по R, подача на оборот
  и на минуту, G96/G97 с пересчётом оборотов по текущему диаметру, инкрементные адреса U/W/V/H,
  смена инструмента, отрезка.
- **Синхронизация каналов** — коды ожидания как рандеву: канал стоит, пока на тот же код
  не придут все каналы, где этот код встречается. Отсюда — честное время цикла и видно,
  кто кого и сколько ждёт.
- **Съём материала** — осесимметричная модель прутка: наружный профиль и осевое отверстие
  вдоль Z. Точение, подрезка, канавки, отрезка, осевое сверление. Считается снятый объём
  и MRR по кадрам.
- **Диагностика** — неизвестные коды, рабочий ход без подачи, несходящиеся радиусы дуг,
  взаимные блокировки каналов, коды ожидания без пары.

## Состояние

Ранний этап. Ядро (`src/core`, `src/sim`) написано на TypeScript, интерфейс ещё собирается.
Целевой диалект — **Hanwha XD** (FANUC-многоканалка); профили Citizen и обобщённого FANUC
лежат рядом в `src/core/dialect.ts`.

**Открытый вопрос — платформа.** Требования: работать в браузере, хоститься на GitHub,
в перспективе собираться в нативное и мобильное приложение. Кандидаты — веб-стек
(TypeScript + WebGL) и Godot 4.7 с веб-экспортом. Решение фиксируется здесь, когда принято.

## Чего пока нет

- Циклы G70–G76, G83 и прочие — распознаются, но траектория не разворачивается.
- Поперечное сверление и фрезеровка приводным инструментом — осесимметричная модель
  их не описывает, такие проходы видны только траекторией.
- Коррекция на радиус при вершине (G41/G42) учитывается только как модальное состояние.
- Генерация УП из геометрии — следующий этап после редактора.

## Допущения модели

- `X` в кадре — диаметр (обычное для токарных станков), в геометрию идёт радиус.
- Торец прутка — `Z0`, материал уходит в минус по Z.
- Координаты противошпинделя пересчитываются в координаты прутка как
  `z_пруток = плоскость_отрезки − z_противошпинделя`.
- Проходной инструмент при радиальном врезании снимает материал до торца заготовки —
  иначе подрезка торца не моделируется. Канавочный и отрезной режут только на ширину кромки.
