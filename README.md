# SwissCAM

Редактор и симулятор управляющих программ для станков продольного точения (swiss-type).

Цель — не «ещё один CAM с деревом операций», а инструмент технолога у станка:
открыть УП, увидеть её глазами станка и поймать ошибку до того, как её поймает шпиндель.

Работает в браузере: **https://liullinil.github.io/swisscam/**
Тот же код собирается в приложение для Windows, Linux, macOS, Android и iOS.

## Что уже делает

- **Разбирает УП** — многоканальные задания. У Hanwha каналы лежат отдельными файлами
  (главный шпиндель и противошпиндель), поддерживаются и заголовки `$1`/`$2`/`$3`
  внутри одного текста.
- **Исполняет модально** — G0/G1/G2/G3, дуги по I/K и по R, подача на оборот и на минуту,
  G96/G97 с пересчётом оборотов по текущему диаметру, инкрементные адреса U/W/V/H,
  цикл G74, смена инструмента, отрезка.
- **Понимает продольное точение** — `G50` со словами осей сдвигает систему координат:
  так возвращают отсчёт Z после вытягивания прутка, и координаты детали остаются сквозными.
  Команды стойки `G150`/`G300`/`G310`/`G340` разбираются и не портят траекторию.
- **Сводит каналы по времени** — парные коды ожидания работают как рандеву: канал стоит,
  пока на тот же код не придут все каналы, где этот код встречается. Отсюда честное время
  цикла и видно, кто кого и сколько ждёт.
- **Снимает материал** — осесимметричная модель прутка: наружный профиль и осевое отверстие
  вдоль Z. Точение, подрезка, канавки, отрезка, осевое сверление; считается снятый объём.
- **Читает таблицу инструмента из программы** — список в шапке и комментарии в кадрах смены
  дают тип, радиус при вершине, диаметр сверла и ширину кромки. Чего в комментариях нет,
  угадывается по характеру движений.
- **Замечает подозрительное** — неизвестные коды, рабочий ход без подачи, несходящиеся
  радиусы дуг, взаимные блокировки каналов, коды ожидания без пары, подачу мимо режима
  (`F200` при `G99` станок отработает буквально).

Заготовка строится на видеокарте: профиль детали лежит в текстуре, а вершинный шейдер
сворачивает плоскую сетку в тело вращения. Снятие материала стоит одной перезаписи
текстуры, а не перестроения меша, — поэтому модель успевает за симуляцией и в браузере
через WebGL2, и на телефоне.

## Как посмотреть

В браузере — по ссылке выше. Локально:

```bash
godot --path . --import
godot --path .
```

Прогон ядра без графики, на эталонных программах из `samples/`:

```bash
godot --headless --path . --script res://test/run_core.gd
```

Снимок окна без запуска руками:

```bash
godot --path . --resolution 1600x900 -- --shot=out.png --at=0.6
```

## Чего пока нет

- Циклы G70–G73, G76, G81–G89 распознаются, но траектория не разворачивается.
- Поперечное сверление и фрезеровка приводным инструментом — осесимметричная модель
  их не описывает, такие проходы видны только траекторией.
- Коррекция на радиус при вершине (G41/G42) учитывается только как модальное состояние.
- Таблица инструмента показывается, но пока не редактируется в интерфейсе.
- Генерация УП из геометрии — следующий этап после редактора.

## Допущения модели

- `X` в кадре — диаметр; знак показывает, с какой стороны подходит инструмент,
  в геометрию идёт `|X|/2`. Проход за центр считается отрезкой.
- Оба канала работают в общей системе координат детали — так печатает постпроцессор
  в эталонных программах. Для стоек, где противошпиндель считает от своего торца,
  в настройках симуляции есть зеркальный пересчёт.
- Границы заготовки, диаметр прутка и сторона свободного торца выводятся из самой
  программы и показываются как догадка, которую можно поправить.

## Устройство

```
scripts/core/   разбор, интерпретатор, планировщик каналов, задание целиком
scripts/sim/    модель прутка, таблица инструмента, прогон с перемоткой
scripts/ui/     окно, редактор, трёхмерный вид, диаграмма каналов
shaders/        тело вращения по текстуре профиля
samples/        эталонные программы Hanwha, на них гоняется ядро
test/           прогон ядра без графики
```
